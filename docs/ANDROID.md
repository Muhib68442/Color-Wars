# Android Packaging and Release

This document is the contract for turning Color Wars into a stable Android app.
It covers what "any Android" realistically means, how the APK is built, how every
game feature maps to the Android shell, and the tests that gate a release.

> **Status:** built and device-tested. The engine, UI, settings, save/resume,
> Grow mode, and the audio/transition UX are complete. The Capacitor shell, app
> icon, versioning, back-button controller, splash screen, and native wake lock
> are in place. Both the `1.0.2` debug APK and a signed release APK have been
> produced; the release APK was installed and played on a device. Those artifacts
> predate the latest UX pass, so run `npm run android:sync` and a release build
> again before publishing. Deployment is still pending.
>
> For the exact Windows commands and the future release checklist, use
> [`RELEASE.md`](RELEASE.md).

---

## 1. Decision

**Web build + Capacitor 8 + Gradle.** The Vite production build is bundled
inside a native Android app. The Pygame prototype in `legacy/main.py` is
archived and is not part of the APK.

What this means in practice:

- The APK contains `index.html`, the compiled JS/CSS, and `font.ttf` as local
  assets. There is no server and no hosted website.
- The app has its own package ID, icon, version, signature, splash screen, and
  Android lifecycle. It is a normal APK/AAB, not a browser shortcut or a
  Trusted Web Activity.
- The WebView renders the UI; native plugins handle storage, back button,
  haptics, splash, wake lock, and system bars.
- The app has **no native `.so` libraries**, so one universal APK works on
  `arm64-v8a`, `armeabi-v7a`, and `x86_64` devices and emulators.

```
src/ ──vite build──▶ dist/ ──cap sync──▶ android/app/src/main/assets/public/
                                              │
                                              ▼
                                   Gradle ──▶ APK / AAB ──▶ device
```

## 2. What "runs on any Android" means

No app can guarantee every Android device ever made. The supported contract is:

| Item                 | Minimum                        | Notes                                                   |
| -------------------- | ------------------------------ | ------------------------------------------------------- |
| Android version      | **7.0 (API 24)**               | Capacitor 8 minimum; covers ~99% of active devices      |
| Compile / target SDK | **36**                         | Capacitor 8 requirement and current Play target         |
| WebView              | Chromium **87+** (2020)        | System WebView updates through Play Store               |
| Architecture         | arm64-v8a, armeabi-v7a, x86_64 | No native libs, so all are supported                    |
| Screen               | 320 dp wide and up             | Phones, tablets, foldables                              |
| RAM                  | 1 GB                           | The game is at most 225 DOM nodes; WebView is the floor |
| Network              | **none required**              | Fully offline after install                             |

Explicitly **not** supported:

- Android 6.0 and older (Capacitor 8 does not support them).
- Devices with an ancient, unupdatable WebView, or Android forks with a broken
  WebView (some non-Google ROMs). The app must show a clear compatibility screen
  instead of a white page or a crash.
- Guaranteed behaviour on modified/rooted firmware.

This is the honest version of "any Android": API 24+ with a modern WebView,
verified on the matrix in §10.

1. Install Android Studio (latest stable, at least Otter 2025.2.1).
2. SDK Manager → install **Android SDK Platform 36**, **Android SDK Build-Tools**,

4. Enable virtualization (WHPX/Hyper-V) for the emulator, or use a physical

   ```powershell

   adb devices
   ```
6. Set `ANDROID_HOME` to the SDK path, or let Android Studio write

## 4. Project configuration

### 4.1 `capacitor.config.ts`

```ts
import type { CapacitorConfig } from "@capacitor/cli";

const config: CapacitorConfig = {
  appId: "com.muhib.colorwars", // permanent; changing it creates a new app
  appName: "Color Wars",
  webDir: "dist",
  server: {
    androidScheme: "https",
  },
  android: {
    backgroundColor: "#0f1115",
    allowMixedContent: false,
  },
  plugins: {
    SplashScreen: {
      launchAutoHide: false,
      launchFadeOutDuration: 500,
      backgroundColor: "#0f1115",
      androidSplashResourceName: "splash",
      showSpinner: false,
    },
  },
};

export default config;
```

`androidScheme: "https"` is Capacitor's default; keep it. Do not enable mixed
content. The package ID must be unique and must never change after publishing.
The native background is dark so a dark-theme launch does not flash; the inline
theme script in `index.html` sets the page palette before first paint, and the
app repaints to light immediately when the saved theme is light. The splash is
hidden from `src/main.ts` after the first screen is ready, with a 350 ms fade as
a fallback if native hide fails. The native `KeepAwake` plugin is registered in
`MainActivity.java`; `@capacitor/keep-awake` does not exist for Capacitor 8.

### 4.2 `vite.config.ts`

```ts
import { defineConfig } from "vitest/config";

export default defineConfig({
  base: "./",                 // relative asset URLs work in the APK and file://
  build: {
    target: "chrome87",       // WebView compatibility floor
    cssTarget: "chrome87",
    sourcemap: true,          // keep for crash triage; remove for smallest APK
  },
  test: {
    environment: "node",
    include: ["tests/**/*.test.ts"],
  },
});
```

Avoid APIs newer than Chrome 87 unless they are feature-detected. No service
worker: the assets are already local, and a stale SW cache is a common cause of
"the app did not update" bugs.

### 4.3 `index.html` head

```html
<meta name="viewport"
      content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover" />
<meta name="theme-color" content="#333333" />
<meta name="color-scheme" content="light dark" />
```

`viewport-fit=cover` is required for edge-to-edge Android 15/16. Pinch-zoom is
deliberately disabled for this fixed board game: `maximum-scale=1`,
`user-scalable=no`, `touch-action: pan-y` on `html`/`body`, and `gesturestart` /
`gesturechange` / `gestureend` blocking in `src/main.ts`. Normal one-finger
scrolling and Android font/display scaling still work; the trade-off is that
users cannot magnify the UI with a two-finger gesture, so text must remain
legible at the supported display settings. A small inline script reads
`color-wars:settings` and sets `data-theme="dark"` plus `theme-color` before
first paint when that theme is saved; the app keeps both values in sync at
runtime.

### 4.4 Android SDK versions — `android/variables.gradle`

```groovy
ext {
    minSdkVersion = 24
    compileSdkVersion = 36
    targetSdkVersion = 36
    // keep the rest of the generated Capacitor 8 values
}
```

Do not raise `targetSdkVersion` independently of Capacitor. Capacitor 8 supports
target 36; a higher target is unsupported until a new Capacitor major.

### 4.5 Manifest and theme

`android/app/src/main/AndroidManifest.xml`:

- `android:screenOrientation="unspecified"` — support portrait and landscape.
- `android:resizeableActivity="true"` — tablets, split screen, foldables.
- Keep Capacitor's `configChanges` list; removing it recreates the WebView on
  rotation and loses state.
- `android:usesCleartextTraffic="false"`.
- No runtime permissions are needed. The template may include `INTERNET`; the
  app makes no network requests. Test with it removed for a strict offline
  build, or keep it and verify airplane-mode behaviour.

`android/app/src/main/res/values/styles.xml`:

```xml
<item name="android:forceDarkAllowed">false</item>
```

Keep `forceDarkAllowed=false`. The game now ships its own light and dark token
sets, so WebView auto-dark would invert the board on top of the chosen theme.
Toggling the app theme updates `<html data-theme>` and `color-scheme`; it does
not change this manifest flag.

### 4.6 Edge-to-edge (Android 15/16)

Android 15 forces edge-to-edge for apps targeting API 35, and Android 16 removes
the opt-out for API 36. Capacitor 8 targets 36, so **the page draws behind the
status and navigation bars** unless it handles insets.

Required:

```css
.app {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
  padding-left: env(safe-area-inset-left);
  padding-right: env(safe-area-inset-right);
}
```

Also use Capacitor 8's system-bars support to set icon/background colours, and
test on API 35 and 36 emulators. This is the most common visual breakage on new
Android versions.

## 6. Runtime behaviour in the shell

### 6.1 Assets and offline guarantee

- Vite writes hashed assets to `dist/`.
- `npx cap sync android` copies them to
  `android/app/src/main/assets/public/`.
- Capacitor serves them through its local `https://localhost` handler.
- No CDN, remote font, API call, or telemetry. `font.ttf` is bundled.
- Verify in airplane mode after a cold start, and with the network inspector.

### 6.2 Lifecycle and save/resume

- Save after every accepted move (debounced ~150 ms) and on `pause`.
- Save schema:
  ```ts
  type SaveV4 = { version: 4; state: GameState; savedAt: number };
  ```

  `GameState` carries `playerCount` (1–4), `hasPlayed` for all four seats,
  `botPlayer` (the AI seat, or `null` for hot-seat), and `growOnly` (the active
  placement rule). Version-2 saves are migrated on load with `botPlayer: null`;
  versions 2 and 3 are migrated with `growOnly: true`.
- Settings are stored separately under `color-wars:settings` as
  `{ version: 7, settings: GameSettings }` (`theme`, `difficulty`, `growOnly`,
  `gridRows`, `gridCols`, `bot`, `profiles`, `sound`, `soundTap`, `soundBot`,
  `soundExplosion`, `explosionStyle`, `vibration`). First-run defaults are Bot
  on, Easy, Grow on, all sounds on, and Pop explosions. Settings v1–v6 are
  normalized on load; a missing or invalid theme becomes `light`, a missing
  `bot` flag follows the default (on), an invalid `bot` flag becomes `false`,
  and missing `growOnly`/sound sub-switches become `true`. An unknown
  `explosionStyle` falls back to Pop. The Grow switch updates the live match as
  well as future games.
- On launch: validate the schema, check the row/column range, player count, Bot
  seat, owner range, and stability. If anything is invalid — including a
  version-1 save — start a new game instead of restoring a corrupt state.
- Use `@capacitor/preferences` on Android; `localStorage` on web. Keep the
  `KeyValueStore` adapter interface identical for both save and settings.
- Test process death with Developer Options → **Don't keep activities**, and by
  force-stopping the app mid-game.

### 6.3 Back button

```ts
import { App } from "@capacitor/app";

App.addListener("backButton", () => {
  if (overlayOpen) closeOverlay();
  else if (inGame) showExitConfirm();
  else App.exitApp();
});
```

Order matters: close overlay → confirm exit from a live game → exit the app.
Test the gesture navigation and predictive back on Android 13+.

### 6.4 Orientation and layout

- Prefer `unspecified` orientation with a responsive rectangular board:

  ```css
  .stage { container-type: size; }
  .board {
    width: min(
      100cqw,
      calc((100cqh - 2 * var(--gap)) * var(--cols, 7) / var(--rows, 7)),
      560px
    );
    display: grid;
    grid-template-columns: repeat(var(--cols, 7), minmax(0, 1fr));
    gap: clamp(1px, 0.7vw, 6px);
  }
  ```

  Cells are square (`aspect-ratio: 1`), so the board fills the stage: a tall
  11×7 board uses the full height and a wide 7×11 board uses the full width.
- Touch targets should stay near **48 dp**; scale cells with the board. At
  15×15 on a narrow phone, cells fall below that size. Pinch-zoom is disabled,
  so accept the smaller visual target (cells remain real buttons with a full
  square hit area) and verify accuracy on the device matrix.
- In four-player mode, keep the P3/P4 side rails readable in portrait; they are
  one card thickness wide (`--score-thickness`, 32–40 px) so the board keeps as
  much width as possible.
- Do not lock orientation unless product decides to; tablets and foldables
  should work in both.
- Test split-screen and foldable posture changes.

### 6.5 Text scaling and accessibility

- Use `rem` / `clamp()` for text, not fixed pixels.
- Test Android Settings → Display → Font size at 200% and Display size at
  maximum.
- Cells are real `<button>`s with `aria-label` (row, column, owner, orbs).
- Turn and win messages live in `aria-live="polite"` regions.
- Ownership must not rely on colour alone; the web build already uses a distinct
  orb fill/ring per player and a text "playing" pill on the active card.
- Test with TalkBack. The WebView exposes the DOM accessibility tree; semantic
  elements are required.
- Respect `prefers-reduced-motion` for cascade animations.

### 6.6 Sound and haptics

- The WebView emits short Web Audio cues for the human tap (`place`), Bot tap
  (`botPlace`), each detonation (`explode`), win, and rejection, plus
  `navigator.vibrate` haptics.
- The Bot cue is a lower two-note pip; the explosion cue fires from the
  animation's `onExplode` callback as each cascade group starts. With reduced
  motion, up to four explosion cues still fire from the final event stream.
- Settings offers four synthesized styles — Pop (default), Boom, Crackle, and
  Fizz — selected with `Sound.setExplosionStyle()`. **Try** previews the current
  style and is gated only by the master Sound switch.
- Audio unlocks on the first user gesture (Android autoplay policy); a rejected
  move before any gesture is silent rather than a crash.
- Pause/mute audio on `pause` and when the app loses focus.
- The **Sound**, **Your taps**, **Bot taps**, **Explosions**, and **Vibration**
  toggles are persisted under `color-wars:settings` and gate every call.
- Replace haptics with a native adapter behind the existing `Haptics` interface;
  it must no-op gracefully on web.
- If WebView audio misbehaves in the background, swap in a native audio plugin
  behind the existing `Sound` interface without touching the controller.

### 6.6.1 Wake lock

- `src/platform/wakeLock.ts` calls the native `KeepAwake` plugin only when the
  match screen is open; `showScreen()` releases it on Home, Settings, How to
  play, and About.
- `KeepAwakePlugin.java` uses `WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON`
  and clears the flag in `allowSleep()` / `handleOnDestroy()`. Web builds use a
  no-op path.

### 6.7 Error handling

- A top-level `window.onerror` / `unhandledrejection` handler shows a recoverable
  error screen with **Restart game** and **Copy diagnostics**.
- Never leave a half-rendered board.
- A startup guard checks that the engine initialized; if not, show the error
  screen rather than a blank page.
- In debug builds, WebView remote debugging is enabled; use
  `chrome://inspect/#devices`.

### 6.8 Performance

- 49–225 DOM nodes; animate with CSS transforms/opacity, not layout properties.
- Replay cascade events with `requestAnimationFrame`, capped so a long chain
  cannot freeze the UI. Each detonation has a 450 ms minimum hold; compression
  for long chains has a 0.65× floor and a ~30 s budget.
- Target: first interactive frame under 1 s on a mid-range device, 60 fps
  animations, no busy loops (unlike `legacy/main.py`, which had no clock).
- Keep the JS bundle under ~150 KB gzip. No framework, no game engine.

`cap sync` copies `dist/` and updates native plugin code. Run it after every web

```powershell
cd android

```

Output: `android/app/build/outputs/apk/debug/app-debug.apk`.

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk

```

```powershell
cd android
.\gradlew.bat assembleRelease
.\gradlew.bat bundleRelease
```

- APK: `android/app/build/outputs/apk/release/app-release.apk` (direct install).
- AAB: `android/app/build/outputs/bundle/release/app-release.aab` (Google Play).

Always test the **release-signed** build on a clean device, not only the debug
build. Debug builds are debuggable, larger, and signed with a throwaway key.

## 8. Signing and versioning

### 8.1 Create the upload key (once)

```powershell
keytool -genkeypair -v `
  -keystore colorwars-release.keystore `
  -alias colorwars `
  -keyalg RSA -keysize 2048 -validity 10000
```

Keep the keystore and passwords in a password manager and a secure backup.
Losing an upload key without Play App Signing means you cannot update the app.

**Never commit** `*.keystore`, `*.jks`, `keystore.properties`, or
`android/local.properties`. They are already covered by `.gitignore`; add the
specific keystore name if needed.

### 8.2 `android/keystore.properties` (not committed)

```properties
storeFile=../../colorwars-release.keystore
storePassword=...
keyAlias=colorwars
keyPassword=...
```

### 8.3 Signing config

```groovy
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file("keystore.properties")
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    signingConfigs {
        release {
            if (keystorePropertiesFile.exists()) {
                storeFile file(keystoreProperties["storeFile"])
                storePassword keystoreProperties["storePassword"]
                keyAlias keystoreProperties["keyAlias"]
                keyPassword keystoreProperties["keyPassword"]
            }
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled false      // keep R8 off for plugin stability
            shrinkResources false
        }
    }
}
```

Enable R8 later only with a tested `mapping.txt` and a plugin smoke test.

### 8.4 Versioning

```groovy
defaultConfig {
    versionCode 10002      // integer, must increase every upload
    versionName "1.0.2"    // user-visible
}
```

This project derives both from `package.json` `version` instead of keeping a
second copy in Gradle (see [`RELEASE.md`](RELEASE.md) §3.1):

- `versionName` = `package.json` `version` (`1.0.2`).
- `versionCode` = `major*10000 + minor*100 + patch` (`1.0.2` → `10002`).
- The About screen uses the same version through Vite's `__APP_VERSION__`.
- Its "Last updated" date comes from `__APP_UPDATED__`: the latest commit date
  (`YYYY-MM-DD`), overridable with the `APP_UPDATED` environment variable.

Bump `package.json` for every release. Never upload the same `versionCode`
twice; keep the mapping recorded per release.

### 8.5 Verify the artifact

```powershell
aapt dump badging app-release.apk | findstr "package: sdkVersion targetSdkVersion uses-permission"
apksigner verify --print-certs app-release.apk
```

Confirm package ID, version, min/target SDK, permissions, and signature before
installing.

## 9. Play Store compliance

- **Target API:** 36 (Capacitor 8). Re-check Play Console each August; Google
  raises the requirement annually.
- **64-bit:** required. The app has no native libs, so the universal build is
  already compliant.
- **Data safety:** declare **no data collected** (no analytics, no ads, no
  network calls).
- **Privacy policy:** provide a short policy even if no data is collected;
  Play requires the Data Safety form and a policy URL for most listings.
- **Content rating:** complete the questionnaire (no violence, no user-generated
  content, no ads).
- **Ads:** declare none.
- **App access:** no login, so "all functionality is available without special
  access."
- **Permissions:** none required. If `INTERNET` remains, explain that the app is
  offline and makes no requests.
- **Families policy:** only relevant if targeting children; the current design
  is "everyone."

## 11. Risks and mitigations

| Risk                                   | Mitigation                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------- |
| Old/odd WebView renders a blank page   | Build target `chrome87`, feature detection, startup check, compatibility screen |
| Android 15/16 edge-to-edge overlaps UI | `viewport-fit=cover` + safe-area insets; test API 35/36                         |
| Gradle/JDK mismatch                    | Android Studio bundled JDK 21, AGP 8.13, Gradle 8.14.3                          |
| App killed, game lost                  | Save on every move and on pause; restore with schema validation                 |
| Upload key lost                        | Play App Signing + secure offline backup                                        |
| Plugin breaks after sync               | Pin Capacitor/plugin versions; smoke test after every `cap sync`                |
| R8 breaks reflection                   | Keep `minifyEnabled false` for v1                                               |
| Store rejection                        | Target 36, Data Safety, privacy policy, content rating                          |
| APK too large                          | No framework; local assets only; target < 15 MB                                 |
| "Works on my phone"                    | Fixed device matrix + Play pre-launch report                                    |

## 12. Release checklist

1. `npm ci && npm test && npm run build` — all green.
2. Bump `versionCode` / `versionName`.
3. `npx cap sync android`.
4. Build a **release-signed** APK and AAB.
5. Install the release APK on a clean physical device; run the §10.2 checklist.
6. Verify the artifact with `aapt` / `apksigner`.
7. Upload the AAB to Play **internal testing**; review the pre-launch report.
8. Fix issues, promote to closed testing, then production.
9. Archive the keystore, `mapping.txt` (if R8), and the exact dependency
   lockfile for the release.
10. Tag the git commit that produced the build.

---

## 13. Definition of done

The Android app is releasable when:

- [ ] All engine and UI tests pass, including the random-game stability test.
- [ ] Feature parity matrix (§5) is complete.
- [ ] The release APK installs and runs on API 24, 30, 34, 35, and 36.
- [ ] Cold start works in airplane mode with no network requests.
- [ ] Save/resume survives process death.
- [ ] Back button and edge-to-edge behave correctly.
- [ ] TalkBack and 200% font scaling are usable.
- [ ] No crash across 100 random games and a 30-minute background/resume cycle.
- [ ] Signed release artifact verifies; permissions match the documented set.
- [ ] Play Data Safety, privacy policy, and content rating are submitted.

## 14. Out of scope for v1.0

- Online multiplayer or accounts (would add `INTERNET`, a backend, and security
  work).
- Ads, analytics, crash-reporting SDKs (each adds permissions/privacy work).
- In-app purchases.
- Cloud save.
- iOS (Capacitor supports it, but it needs macOS/Xcode and is not part of this
  plan).
